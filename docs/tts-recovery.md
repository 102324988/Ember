# 语音服务 403 修复

日期：2026-10-21。

## 原因和修复

实际日志显示 Edge 语音 WebSocket 握手返回 HTTP 403。Ember 环境安装的是 `edge-tts 7.2.7`，其请求使用旧版鉴权格式。上游 [7.3.0](https://github.com/rany2/edge-tts/releases/tag/7.3.0) 已加入 Sec-MS-GEC v2 支持，[7.3.1](https://github.com/rany2/edge-tts/releases/tag/7.3.1) 又修复了服务日期解析。

已将当前 Ember Python 环境更新到正式版 `7.3.1`，项目依赖要求改为 `edge-tts>=7.3.1,<8`。未修改第三方包源码，也未切换语音提供方或修改数据库。

另一个错误是旧 TTS 实现捕获异常后返回 `None`，随后服务端执行 `len(None)`，导致原始错误被掩盖。现在成功时必须返回非空音频；失败时传递明确的错误分类：HTTP 拒绝、限流、网络、超时或无音频。日志和前端提示不包含服务请求 URL 或令牌。

自动语音失败也会发送带 `message_id`、`turn_id` 的 `tts_error`。手动重播仍只回复发起它的连接，并保留 `request_id`。静音、取消或旧轮次的迟到错误不会覆盖当前播放状态。

## 生效方式

当前环境已安装更新，**需要重启后端**，使进程重新导入语音库和项目代码。开发前端会自动刷新；使用静态部署时重新构建并发布前端。

其他环境在项目根目录运行：

```powershell
conda activate Ember
python -m pip install "edge-tts>=7.3.1,<8"
python -m pip show edge-tts
```

等待当前对话结束后，在原后端终端按 Ctrl+C，再按原方式启动。回到页面刷新，点击既有回复的“重播这句”即可验证，无需发送新对话。

## 验证

- 更新后独立调用 Edge 库，以及通过项目 `TTSManager` 各合成一次固定测试句，均返回 **17,712 字节** MP3 数据。
- 未使用用户聊天正文，未启动新的业务后端或调用对话模型。
- 自动测试模拟 403、429、503、网络失败、超时、空音频和取消；协议测试检查自动错误广播与消息关联。
- 浏览器检查覆盖自动/手动错误提示、再次重播恢复和正文保留。
- 最终回归：Python 143 项、前端单元 18 项、浏览器 20 类交互与 10 种宽度/视图组合通过；lint 和生产构建通过。构建仍保留既有 Live2D 大包提示。

若后续仍出现 403，先检查后端使用的 Python 环境与版本，再检查现实系统时间和网络；逻辑世界时钟不会参与 TTS 鉴权。超时或服务限流时可稍后点击“重播这句”，避免连续点击。

## 回退

项目错误处理可随版本回退，不涉及数据迁移。恢复旧环境包的命令为 `python -m pip install edge-tts==7.2.7`，但旧版本可能重新出现本次 403，不作为当前恢复方案。
